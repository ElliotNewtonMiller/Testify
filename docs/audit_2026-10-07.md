# App audit — 2026-10-07

This is a findings list. Items marked ✅ have been fixed since; the rest are still open. The role templates and the template-based test accounts are out of scope and stay as they are.

Suggested starting point: items 1–6, which make a real deployment unsafe or broken.

## Blocks a real deployment

1. ✅ **Fixed 2026-10-07** (migrations are now tracked and run only once; see CLAUDE.md). **The database schema can only be created once.**
   - `migration001.up()` (`packages/db/src/migrations/001_initial_schema.ts`) runs on every server start (`apps/server/src/server.ts`).
   - It uses plain `createTable`, with no "if not exists" and no migrations table.
   - Against a persistent Postgres, the second start crashes, and future schema changes have no upgrade path.
2. ✅ **Fixed 2026-10-07** (the server refuses to start without `DATABASE_URL`; `memory` is an explicit dev-only opt-in; see CLAUDE.md). **A missing `DATABASE_URL` silently uses a throwaway in-memory database** (PGlite). All data is lost on restart.
3. ✅ **Fixed 2026-10-07** (generated or `ADMIN_PASSWORD` first-admin password, forced change, hints removed; see CLAUDE.md). **The default admin is `admin` / `password`** (`UserRepository.seedInitialAdmin`).
   - The login page shows these credentials twice: under the form, and in the "Forgot password" dialog (`apps/web/src/components/LoginPage.tsx`).
   - Nothing forces a change.
4. ✅ **Fixed 2026-10-07** (route deleted; see CLAUDE.md). **`GET /api/v1/executions/verify` needs no login** (`server.ts`). It returns every result, step result and audit log entry.
5. ✅ **Fixed 2026-10-07** (permission ceiling, rank and last-admin rules on every admin change; see CLAUDE.md). **Privilege escalation.** Every admin route only requires `USER_MANAGE` (`apps/server/src/routes/admin.ts`). Anyone holding it can:
   - create a role containing `SYSTEM_ADMIN`,
   - give themselves the Admin role,
   - add a `SYSTEM_ADMIN` permission override.

   Nothing stops disabling or demoting the last admin either.
6. ✅ **Fixed 2026-10-07** (the project is resolved from the ids every route names; see CLAUDE.md). **Project scoping can be bypassed.** Routes not nested under `/projects/:projectId/...` skip the API-token project check, and also evaluate user permissions globally (per-project role overrides are ignored). A token for project A can read or write project B through:
   - `POST /api/v1/executions`
   - plan membership: `GET` / `POST` / `DELETE /api/v1/test-plans/:planId/cases`, and the suite cascade
   - `GET /api/v1/test-cases/:id/latest-version`
   - custom-field values for cases and suites

## Security

7. ✅ **Fixed 2026-10-08** (all seven reads need SPEC_VIEW per project; the project list is filtered; see CLAUDE.md). **Read routes only check login, not `SPEC_VIEW`:** projects, plans, runs, the spec tree, case content, plan cases, and custom-field values.
8. ✅ **Fixed 2026-10-08** (server-side sessions; sign-out and password changes end them; a password change needs the current one; see CLAUDE.md). **Sessions are weak:**
   - Changing your password doesn't require the current one, so a stolen token is enough to take over the account.
   - Logout does nothing on the server, and tokens can't be revoked.
   - A password change doesn't end other sessions.
9. ✅ **Fixed 2026-10-08** (20-strike account lock for 15 minutes, 50-failure per-address limit, admin Unlock; see CLAUDE.md). **No login rate limiting or lockout.**
10. ✅ **Fixed 2026-10-08** (a global handler logs unexpected errors and answers a generic 500 with a request id; see CLAUDE.md). **Server errors expose internals.** Fastify's default 500 response includes database error messages, and some routes return `err.message` directly.
11. ✅ **Fixed 2026-10-08** (no cross-origin access unless listed in `CORS_ORIGINS`; see CLAUDE.md). **CORS allows any origin** (`origin: '*'`).
12. ✅ **Fixed 2026-10-08** (a token works only while its issuer is active and still manages tokens, with no more than the issuer's current permissions; disabling the issuer revokes them; see CLAUDE.md). **API tokens never expire by default**, and keep working after the admin who issued them is disabled or demoted.
13. ✅ **Fixed 2026-10-08** (formula-like text gets an apostrophe in every CSV; the importer removes it; see CLAUDE.md). **CSV exports don't neutralise spreadsheet formulas.** A cell starting with `=` executes when opened in Excel.
14. ✅ **Fixed 2026-10-08** (AES-256-GCM with a `SECRETS_KEY` kept out of the database; see CLAUDE.md). **The SMTP password is stored in plaintext** in `system_settings`.
15. ✅ **Fixed 2026-10-09** (the web app signs in with an HttpOnly, SameSite=Strict cookie plus a CSRF header; see CLAUDE.md). **The login token is kept in `localStorage`**, which page scripts can read.
16. **Import accepts JSON bodies up to 140 MB**, all held in memory.
17. **Custom-field validation regexes run as written** (ReDoS risk; admin-only).

## Bugs

18. **Execute mode shows two fake test cases** (TFY-101, TFY-102) when no plan is selected or a load fails (`DEFAULT_FALLBACK_WORKSPACE` in `apps/web/src/App.tsx`).
19. **`POST /api/v1/executions` stores any verdict string.** An invalid `test_step_id` causes a 500.
20. **`EXECUTE_OVERWRITE` is never enforced.** Anyone with `EXECUTE_RUN` can overwrite results.
21. **Batch results** (`apps/server/src/routes/batchExecution.ts`):
    - No transaction: rows are inserted one at a time, so a failure part-way leaves a partial batch. This is also slow, and the likely cause of the flaky 1000-item test.
    - Atomic mode leaves auto-linked plan cases behind when the batch is rejected.
    - A step result with an unknown `step_number` is quietly recorded against step 1.
    - Verdicts aren't validated.
22. **Admins can't reset another user's password**, even though the login page tells users to ask an admin.
23. **Concurrent case creation can collide** on external id, giving a 500 (`getNextExternalId` against the unique constraint).
24. **Audit log entries are wrong:** `ip_address` is hardcoded to `127.0.0.1` (24 places), and `user_agent` holds made-up names.
25. ✅ **Fixed 2026-10-07** (with item 3). **Login calls `seedInitialAdmin()` on every attempt.**
26. **An open case keeps showing old custom-field values** after an admin edits or deletes that field.

## Missing for production

27. No README, deployment guide, CI, or Docker setup.
28. No health endpoint and no request logging (`logger: false`). No startup config validation: a missing `JWT_SECRET` only warns.
29. **No production build path.**
    - The server runs under `tsx`, a development runtime.
    - Nothing serves the built web app; only Vite's dev proxy does.
30. No per-project access control: every user sees every project.
31. Sessions expire after 1 hour with no renewal.
32. No rate limits on exports, report emails, or API tokens.
33. **Unused columns:**
    - `custom_fields_snapshot` is never populated, so results don't record custom-field values.
    - `test_plan_cases.assigned_user_id` is never used.
